## 1. Internal Architecture & Core Concepts
- **Capacitor Columnar Format**: Encodes columns with run-length, dictionary, and bit-packed compression. Prunes unreferenced columns before scanning.
- **Borg Compute Slots**: Dynamic slot allocator. On-demand queries compete for a pool of shared slots; BigQuery Editions provide dedicated slot reservations with autoscaling.
- **Partitioning vs Clustering**: Partitioning divides tables physically by ingestion time or DATE column (max 4,000 partitions). Clustering sorts data by up to 4 columns within partitions for block-level skipping.

---

## 2. Production Failure Modes & War Stories (4 YoE)
### ⚠️ Slot Starvation & Execution Spill to Disk
Complex multi-way joins with unpartitioned data exhaust available slots; intermediate stages spill to persistent shuffle disk, causing query latency to spike from 10s to 30 mins.

### ⚠️ Partition Pruning Failure
Wrapping a partitioned column in a SQL function (e.g. `WHERE DATE(timestamp_col) = ...` instead of `WHERE timestamp_col >= ...`) causes BigQuery to perform a full table scan, multiplying cost 50x.

## 3. Production Scale & Metrics Benchmarks
- Scanned volume reduced from 14 TB to 120 GB per run using ingestion-date partitioning and clustering on `user_id, status`.
- Average monthly BigQuery spend optimized by 38% after implementing reservation commitments with 100 baseline slots and 200 autoscale ceiling.

## 4. Top 4-YoE Interview Questions & Spoken Answers
### Q1: How do you optimize a query scanning multiple terabytes in BigQuery?
**Spoken Answer:**
> "First, check execution details in INFORMATION_SCHEMA.JOBS to see slot usage and spilled bytes. Apply DATE partitioning to restrict scanned blocks, cluster by high-cardinality filter columns, avoid SELECT *, and pre-filter with CTEs before heavy joins."

### Q2: When would you choose BigQuery Editions over on-demand pricing?
**Spoken Answer:**
> "When query patterns are steady, predictable, or exceed $10,000/month in on-demand scanning costs ($6.25/TB). Editions (Standard, Enterprise, Enterprise Plus) allow reserved slot commitments, budget caps, and autoscaling slots with VPC service controls."

## 5. Production Code / SQL Blueprint
```sql
-- Optimized BigQuery MERGE with Partition Pruning
MERGE INTO dataset.fact_events T
USING dataset.stg_events S
ON T.event_date = S.event_date AND T.event_id = S.event_id
WHEN MATCHED THEN UPDATE SET T.updated_at = CURRENT_TIMESTAMP(), T.payload = S.payload
WHEN NOT MATCHED THEN INSERT (event_date, event_id, payload, created_at)
VALUES (S.event_date, S.event_id, S.payload, CURRENT_TIMESTAMP());
```
